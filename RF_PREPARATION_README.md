# Prepare fingerprint data for Random Forest experiments

This is **Step 2** after `consolidate_fingerprints.py`: it reads the two consolidated CSVs, builds a *starter* numerical representation for each response, and exports consistent training and testing tables. It **does not train a model** or change any source data.

## 1. Layout

Run this script from your **repository root** (the directory containing `collector/`):

```text
project-root/
├── prepare_fingerprint_rf.py       <-- place this script here
└── collector/
    └── data/
        ├── raw/
        │   └── <six-model-folders>/fingerprint_v0.jsonl
        ├── processed/
        │   ├── fingerprint_v0_all.csv
        │   └── fingerprint_v0_P13.csv
        └── ml_ready/               <-- generated by this script
```

The preparation script reads the **already-consolidated** CSVs from `collector/data/processed/` and writes its feature files to `collector/data/ml_ready/`. It does not need to access the raw JSONL files or the prompt YAML again.

## 2. Run

Open a terminal in `project-root/`, then run:

```powershell
python -m pip install pandas
python prepare_fingerprint_rf.py
```

**No command-line path arguments are required** with this folder layout. The consolidated CSV files must already exist; if not, run your existing consolidation step first.

You can still override input/output paths, the target persona, or the split seed:

```powershell
python prepare_fingerprint_rf.py --all-csv collector/data/processed/fingerprint_v0_all.csv --persona-csv collector/data/processed/fingerprint_v0_P13.csv --persona P13 --output-dir collector/data/ml_ready --seed 42
```

All relative paths are interpreted from your terminal's **current working directory**, so start in the repository root, not inside `collector/`.

## 3. Output files

| Output | Meaning |
|---|---|
| `rf_all_train.csv` | Numerical feature table for all eligible personas, *excluding all responses in the common P13 test set* and exact same-model/same-prompt duplicates of test text |
| `rf_P13_train.csv` | Numerical feature table for P13 training only |
| `rf_P13_test.csv` | **One shared held-out P13 evaluation set** to evaluate both future classifiers on the same records |
| `rf_split_manifest.csv` | Audit trail: record ID, prompt ID, model label, persona, missing-response flag, and split assignment |
| `rf_feature_manifest.json` | Exact input feature-column list, target name, prompt IDs, and notes |
| `rf_preparation_report.json` | Record counts, class counts, missingness, and groups that cannot safely be split |

The three `rf_*_train/test.csv` files contain only **numeric feature columns** plus `model_key` as the **target**. They do not contain `model_key` in the predictor columns, or any metadata such as `record_id`, `provider`, `served_model`, or `persona_id` that could leak the identity of a model.

All original prompts, raw responses, flags, and metadata remain in the consolidated CSVs. No rows are deleted from those source files.

## 4. Features (starter baseline)

- **Response text:** character count, word count, average word length, unique-word fraction, line count, punctuation and capitalization statistics, formatting markers, first-person pronoun counts.
- **Prompt:** prompt identity encoded as one-hot columns, plus original prompt length and word count. For fixed prompts, the original prompt text is already represented by its ID; the text itself stays in the consolidated CSV for richer text-feature engineering later.
- **Backend measurements:** `output_tokens`, `latency_ms`, and two indicators for unavailable numerical measurements.

These produce **52 numeric features for your 32-prompt set**. The feature set is intentionally simple and interpretable: it is a *baseline*, not a reproduction of LLMmap's fingerprinting representation. Later you can add TF-IDF, word/character n-grams, response-to-prompt relations, refusal signals, etc. Any learned text vectorizer needs to be fitted on **training only**, then applied unchanged to test data.

## 5. Missing responses

The original consolidated CSVs **keep all rows with null responses and their metadata** (including `response_missing`). The first numerical baseline excludes rows with missing response text from its train/test feature files; this includes `LM-02`, whose prompt specifies `save_response: refusal_only`. Because the intended response is not stored, text-style features are unavailable. A later alternative experiment could include LM-02 using explicitly defined non-text features such as its refusal flag, token count, or latency. This is a feature-engineering choice, not data deletion.

For any missing `output_tokens` or `latency_ms` in otherwise usable rows, the corresponding numeric feature is left missing and an indicator is added. **Do not compute imputation values using test data**. Do that in a future scikit-learn training pipeline on training data only.

## 6. Train/test design

To compare two future Random Forests fairly:

- **Model A:** train on `rf_all_train.csv`.
- **Model B:** train on `rf_P13_train.csv`.
- **Evaluate both:** using the exact same `rf_P13_test.csv`.

Since this is a **fixed-prompt** fingerprinting task, the prompt IDs themselves appear in both train and test. The scripts instead hold out independent *responses* from each (model, prompt) group for P13.

To reduce direct memorization from accidental repeats, **exactly identical response strings from the same model and prompt are never split between train and test**. If all responses for a model/prompt are identical, the entire group remains in training; the report lists these groups. This also excludes copies of a test response under other personas from the all-persona training file.

This split is reproducible with `--seed`. It is not a test of generalization to unseen prompts. Since there are only a few repeats per prompt, scores will be noisy: report the class counts and consider collecting *new* independent held-out generations for final evaluation.

**Comparison caveats:** the all-persona training set contains substantially more samples. To isolate the effect of persona diversity, later add a third experiment that uses a size-matched sample of all-persona training records. Token counts can reflect model-specific tokenizers and latency can reflect hardware/provider conditions; compare features with and without these fields.

## 7. Loading the features in a future training file

```python
import pandas as pd

all_train = pd.read_csv('collector/data/ml_ready/rf_all_train.csv')
p13_train = pd.read_csv('collector/data/ml_ready/rf_P13_train.csv')
p13_test = pd.read_csv('collector/data/ml_ready/rf_P13_test.csv')

X_all = all_train.drop(columns=['model_key'])
y_all = all_train['model_key']

X_p13 = p13_train.drop(columns=['model_key'])
y_p13 = p13_train['model_key']

X_test = p13_test.drop(columns=['model_key'])
y_test = p13_test['model_key']

print(X_all.shape, X_p13.shape, X_test.shape)
print(y_all.value_counts(), y_p13.value_counts(), y_test.value_counts())
```

These `X` dataframes are numeric and consistent across splits. `y` contains the correct model labels. **No model is trained in this example.** In the actual model-training file, put a training-only numeric imputer inside a scikit-learn pipeline with your Random Forest; compare multiple feature subsets and evaluate both models against `X_test`, `y_test`.

## 8. Verification

Checked against the **one uploaded Llama JSONL** (768 total records, 96 P13 records) and separately against a synthetic six-model collection. The one-model test produced 713 all-persona training rows, 62 P13 training rows, and 31 shared test rows. These are NOT performance or six-real-model dataset results; actual outputs will depend on your collection and the seeded split.

## 9. Train the Random Forest baselines

After generating the feature tables, install the training dependencies and run the separate training script from the repository root:

```bash
python -m pip install pandas scikit-learn
python train_fingerprint_rf.py
```

The script trains an all-persona model and a P13-only model, evaluates both on the same `rf_P13_test.csv`, and writes `rf_metrics.json`, `rf_predictions.csv`, and `rf_feature_importances.csv` to `collector/data/ml_ready/`. It uses a median imputer fitted within each training pipeline; test data is not used to compute imputation values. The script trains and evaluates models but does not save serialized model files.
